## 2) اكتشافات إضافية (خارج التقرير الأصلي)
1. `120_bookings_property_management.sql` يكسر التثبيت النظيف ولوّث `schema-expected.json` ← نُقل إلى `db/legacy/`.
2. دور `cashier` كان يرى الرواتب وIBAN والهوية ← صار الكامل لـ accountant/admin فقط.
3. ثغرات حرجة/عالية في `@fastify/jwt` و`@fastify/static` ← رُقّيا (يتطلب تعديل `setHeaders`).
4. إنشاء موظف براتب كسري كان يفشل (`22P02`)، وتاريخ غير صالح كان يعطي 500.
5. `PUBLIC_RATE_LIMIT_MAX` كان يعمل في الإنتاج رغم التعليق.
6. اختبار الحجز كان مرتبطاً بسعر ثابت ويفشل مع بيانات العرض.

## 3) تغييرات سلوك تحتاج موافقتكم/انتباهكم
- مسارات الرواتب/العهد/المصروفات وتقاريرها صارت `accountant` فأعلى (viewer/cashier يفقدون تلك الشاشات؛ لم تُختبر الواجهة بحساباتهم).
- `migrate-cli` يخرج بكود 1 عند الفشل (يوقف api في Compose). الاستثناء: `MIGRATE_ALLOW_FAILURE=1`.
- ترحيل جديد `210_idempotency.sql` (المخطط 0.10.0)؛ ترويسة `Idempotency-Key` اختيارية.
- أخطاء قيود قاعدة البيانات تُرجع رسالة عامة (الحالة 422 كما كانت).

## 4) المخاطر المتبقية
1. **ACC-R1:** `post_entry()` يمتص أي فرق ≤ 0.05 ريال في الحساب 5910 لأي قيد (لا لقيود العملات الأجنبية فقط). لم يُغيَّر؛ مُثبَّت باختبار ويحتاج قراركم.
2. جداول الرواتب/العهد/المصروفات تمنح `erpx_app` INSERT/UPDATE/DELETE مباشرة (عكس دفتر الأستاذ المحمي) — يلزم نقلها إلى دوال SECURITY DEFINER.
3. قفل الدخول لكل مستخدم في ذاكرة العملية (لا يُشارَك بين النسخ)؛ التخفيف الحالي: حد Nginx لكل IP فقط.
4. لم يُشغَّل: Docker build/compose، CI على GitHub، شهادة TLS حقيقية، متصفحات/أجهزة، أحمال > 100 طلب متوازٍ، مليون قيد.
5. قواعد قائمة طبّقت الملف الزائد 120 تحتفظ بكائناته (غير ضارة، لا يستخدمها الكود).
6. `erpx_app` ما زال يملك صلاحيات DML على `idempotency_keys` (سجل مساعد لا يغيّر بيانات مالية).
7. لا نسخة احتياطية دورية مُجدولة: السكربتات جاهزة لكن `cron` والنسخ خارج الخادم مسؤولية النشر.
