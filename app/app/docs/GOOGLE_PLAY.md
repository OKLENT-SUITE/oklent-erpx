# النشر على Google Play

المنتج الحالي **تطبيق ويب تقدّمي (PWA)** بواجهة عربية RTL، فيمكن تغليفه كتطبيق أندرويد بطريقتين دون إعادة كتابة:

## الطريق أ — TWA بـ Bubblewrap (الأسرع)
1. انشر الخدمة على نطاق **HTTPS** عام (Nginx + Let's Encrypt)، مثال `https://erpx.oklent.net`.
2. تأكد أن `manifest.webmanifest` والأيقونات 192/512 تعمل (Lighthouse ← PWA).
3. ```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://erpx.oklent.net/manifest.webmanifest
bubblewrap build        # ينتج app-release-bundle.aab + مفتاح التوقيع
```
4. اربط النطاق: ضع `/.well-known/assetlinks.json` ببصمة SHA-256 للمفتاح (يعرضها `bubblewrap fingerprint`).
5. ارفع ملف `.aab` في Play Console.

## الطريق ب — Capacitor
مناسب إذا أردت إضافات أصلية (بصمة، إشعارات). `npm i @capacitor/core @capacitor/cli @capacitor/android` ثم `npx cap add android` واجعل `server.url` يشير للنطاق أو انسخ ملفات `web/`.

## متطلبات Play Console (راجعها من الموقع الرسمي لأنها تتغير)
- حساب مطوّر (رسم تسجيل لمرة واحدة) وتوثيق الهوية، وللحسابات الشخصية الجديدة قد يُشترط اختبار مغلق بعدد من المختبرين لمدة محددة قبل الإنتاج.
- مستوى Target API الأحدث المطلوب، وتوقيع Play App Signing.
- **سياسة خصوصية** بعنوان عام (بيانات الفواتير بيانات مالية)، ونموذج «أمان البيانات».
- لقطات شاشة، أيقونة 512، رسم ميزات 1024×500، وصف عربي/إنجليزي.
- تصنيف المحتوى، وإقرار بعدم الإعلان إن لا يوجد.

## قبل النشر للجمهور (ضروري)
1. غيّر `JWT_SECRET` وكلمات المرور، فعّل HTTPS وHSTS، وقيّد CORS ومعدل تسجيل الدخول (Rate limit).
2. نفّذ المرحلة الثانية من ZATCA إن كان التطبيق سيُصدر فواتير حقيقية.
3. نسخ احتياطي مجدول واختبار استعادة.
4. مراجعة أمنية (ثغرات XSS في عرض النصوص، صلاحيات الأدوار) واختبار حمل.
